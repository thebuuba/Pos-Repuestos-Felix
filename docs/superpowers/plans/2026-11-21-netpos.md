# Migración NetPOS Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [x]`) syntax for tracking.

**Goal:** Cargar el inventario real y conservar toda la exportación NetPOS en una base aislada, accesible mediante la interfaz operativa aprobada, dejando una carga remota revisable.

**Architecture:** Extender la precisión de las operaciones existentes, sin reemplazar su protocolo transaccional. Preparar el origen con Python estándar y cargarlo atómicamente mediante PostgreSQL/psql; originales comprimidos y tablas de historia privadas. Mantener el snapshot operativo separado de la historia masiva.

**Tech Stack:** pnpm, Node/pg, PostgreSQL 17, Python 3.11 stdlib, React/Radix recuperados de Polymet, Playwright/Edge instalado.

**Spec:** `docs/superpowers/specs/2026-11-21-netpos-design.md`

## Global Constraints

- Trabajar en `feat/sistema-unificado-offline`; conservar `main`.
- pnpm solamente; no dependencias nuevas si las herramientas instaladas bastan.
- No migraciones ni escrituras de prueba en la base real. Datos, credenciales y SQL con filas reales fuera de Git y de recursos públicos.
- Mantener Polymet según `design-system/repuestos-felix/MASTER.md` y `docs/design/polymet-reference.json`.
- Cantidades/mínimos con dos decimales, costo/precios unitarios con cuatro, importe final con dos; códigos exactos sensibles a mayúsculas.
- No doble conteo de stock/deuda ni emisión de NCF históricos como nuevos.
- Conservar idempotencia, versiones, prueba de confirmación durable y compatibilidad de respaldos anteriores.
- Español, DOP/RD$, es-DO, America/Santo_Domingo.
- No incluir datos reales en pruebas, commits o logs públicos.

Sin importación devuelve listas vacías e importada=false. Snapshot incorpora `state.catalogo` con esos valores; nunca carga filas históricas ni columnas de personas o pagos.
- Corrección del perfil real: once PRECIO2 tienen tres decimales genuinos. Ampliar precios unitarios de productos, detalle de venta y tarifas de detalle de compra a numeric(16,4), manteniendo máximos. Reutilizar costUnits para unidades de escala10000; total de venta=halfUp(precioUnits*cantidadUnits/10000). Persistir precio unitario exacto y redondear solo el total por línea. Snapshot conserva números compatibles y añade cadenas exactas: producto `preciosExactos:{p1,p2,p3}`, detalle de venta `precioExacto` y detalle de compra `preciosExactos:{p1,p2,p3}`. Proveedor/formulario exponen `pricesExact` y reabren/envían las cadenas sin pasar por Number; mantener precios numéricos para presentación. El respaldo v5 de esta rama, aún sin publicar ni datos del negocio, admite precios unitarios4dp; v2-v4 mantienen precios2dp. El loader verifica las escalas del destino y aborta si el esquema truncaría datos.

Usar COPY binario con campos TEXT en staging (stdlib struct para encabezado/longitudes/datos UTF-8/trailer), después convertir a tipos finales. Para histórico se puede codificar ordinal bigint explícito o promover desde staging texto. PostgreSQL 17 CopyFromErrorCallback binario informa línea/columna sin valores; comprobarlo mediante marca sintética y fallo truncado en logs de servidor predeterminados. Conservar artefactos revisables/hash y los originales gzip/base64, sin literales de datos en SQL. Mínima implementación sin encoder numérico propio. Actualizar manifiesto/loader/paquete y pruebas según transporte binario. Exigir verify-full para host remoto (rechazar downgrade explícito); local puede desactivar TLS. No introducir dependencias.
